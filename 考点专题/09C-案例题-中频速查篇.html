①风险管理 · 7 次 / 123 分

7 过程 + 应对策略（填空必背）

规划风险管理 → 识别风险 → 定性风险分析 → 定量风险分析 → 规划风险应对 → 实施风险应对 → 监督风险
消极风险（威胁）积极风险（机会）
规避：消除原因 / 改计划开拓：确保机会一定发生
转移：外包 / 保险 / 合同条款分享：分给第三方共同争取
减轻：降低概率或影响提高：提高概率或正面影响
接受：被动 / 主动（留应急储备）接受：机会来了就顺势利用
上报：超出项目经理权限时上报高层 —— 对威胁和机会都适用

两个常考概念

  • 风险值 = 概率 × 影响，配合概率影响矩阵定风险等级
  • 应急储备：应对「已知-未知」风险，项目经理可直接动用，在成本基准内
  • 管理储备：应对「未知-未知」风险，须高层审批，不在成本基准内（总成本 = 成本基准 + 管理储备）
  • 风险审计：检查风险应对措施的有效性 + 风险管理过程的有效性
  • 风险登记册：始于识别风险过程，全项目持续更新

「风险管理方面存在的问题」找错清单

  1. 未制定风险管理计划无风险偏好、无概率影响矩阵、无风险预算
  2. 风险识别不充分只靠项目经理一人，未全员参与，未用专家判断/头脑风暴/德尔菲/SWOT
  3. 只识别威胁不识别机会
  4. 未做定性/定量分析没有优先级排序，眉毛胡子一把抓
  5. 无风险登记册或登记册未随项目推进更新
  6. 无风险责任人识别了风险但没人认领、没人跟踪
  7. 无应对措施或措施与风险严重程度不匹配
  8. 储备缺失或混用无应急储备；或把管理储备当应急储备用了
  9. 未做风险监控 / 风险审计
  10. 风险发生后才被动应对说明前期监控完全失效

②采购与招投标 · 5 次 / 88 分

招投标法定数字（背死，判断+找错双杀）

≥ 20 日招标文件发出 → 投标截止
15 日前招标文件澄清 / 修改须发出
5 人以上单数评标委员会人数
≥ 2 / 3技术经济专家占比
≥ 3 日中标候选人公示期
30 日内发中标通知书 → 签合同
≤ 2%（≤80 万）投标保证金
≤ 10%履约保证金（合同金额）
10 日前 / 3 日内对招标文件提异议 / 招标人答复
28 天索赔答复期限
可不招标的情形：涉及国家秘密/安全、抢险救灾、需采用不可替代的专利或专有技术、采购人依法能够自行建设、需向原中标人采购否则影响施工/功能配套。

情形选什么风险承担
范围 / 需求明确总价合同 FP卖方可风险大
范围不清、需尽快开工成本补偿合同 CP买方可风险大
范围/量均不定、短期小规模工料合同 T&M双方分担
工作量大、工期长、单价明确单价合同按实结算

「招投标方面存在的问题」找错清单

  1. 应招标而未招标直接指定供应商；或化整为零规避招标
  2. 招标文件编制不规范含歧视性、倾向性条款，指定品牌或特定供应商
  3. 时间节点违规不足 20 日、澄清不足 15 日
  4. 评标委员会组成不合规人数非单数、专家比例不足、有利害关系者未回避
  5. 招标人与投标人串通开标前泄露标底、泄露其他投标人信息、暗示报价
  6. 开标前开启投标文件并透露给他人
  7. 中标候选人未公示或公示期不足 3 日
  8. 未在 30 日内签合同或所签合同与招标文件实质性内容不一致
  9. 中标人转包或违法分包
  10. 资格预审 / 资格后审程序错误

「合同管理方面存在的问题」找错清单

  1. 合同条款不明确范围、验收标准、知识产权归属、付款节点
  2. 无 SOW 或 SOW 不完整工作说明书缺：工作范围、交付物、验收标准、期限、地点
  3. 合同变更未签补充协议口头答应就算变更
  4. 未做合同交底项目团队不了解合同要求
  5. 索赔流程不当或超期未在 28 天内提出索赔通知
  6. 无合同管理台账合同文档未归档、付款与交付不匹配
  7. 验收无书面确认未取得客户签署的验收报告

③资源管理 · 6 次 / 107 分

必背理论（填空高频）

  • 团队发展 5 阶段：形成 Forming → 震荡 Storming → 规范 Norming → 成熟/发挥 Performing → 解散 Adjourning
  • 震荡期特征：成员间争执、互相指责、怀疑领导能力 —— 案例最爱考"判断当前处于哪个阶段"
  • 冲突解决 5 种（由弱到强）：回避/撤退 → 缓和/包容 → 妥协/调和 → 强迫/命令 → 合作/解决问题（合作最优、双赢）
  • 马斯洛 5 层次：生理 → 安全 → 社交（归属）→ 尊重 → 自我实现
  • 赫兹伯格双因素：保健因素（工资、工作条件、公司政策 → 消除不满）+ 激励因素（成就、认可、责任、成长 → 产生满意）
  • 项目经理 5 种权力：法定（合法）、奖励、强制（惩罚）、专家、感召（参照）
  • X 理论（人性惰、需强制）／Y 理论（人主动、愿负责）
  • RAM / RACI：确保每个工作包只有一个明确责任人（R 负责、A 批准、C 咨询、I 知情）

「人力资源管理方面存在的问题」找错清单

  1. 无人力资源管理计划 / 人员配备管理计划无资源日历，谁何时在岗不清楚
  2. 人员技能与岗位不匹配未做技能培训、未评估能力
  3. 一人身兼多职 / 资源冲突关键人员被同时抽调到多个项目
  4. 团队处于震荡期未有效引导冲突未及时干预，内耗严重
  5. 冲突处理方式不当一味回避（问题累积）或一味强迫（士气受损）
  6. 无激励机制只靠加班压任务，忽视马斯洛/双因素需求
  7. 沟通不足信息不透明，成员不了解项目目标与进展
  8. 无责任分配矩阵职责边界模糊，出问题互相推诿
  9. 无绩效考核或考核标准不公平、不公开
  10. 人员离职无知识转移无文档沉淀、无备份人员

④挣值 EVM · 速查（案例必拿分）

完整讲解见 ① EVM 挣值分析专题，这里只放冲刺速查。

绩效（现状） CV = EV − AC <0 成本超支 SV = EV − PV <0 进度落后 CPI = EV / AC <1 超支，>1 节约 SPI = EV / PV <1 落后，>1 超前 预测（未来 · 关键看典型 / 非典型） ① 剩余按原预算完成（非典型 · 已纠偏） ETC = BAC − EV EAC = AC + (BAC − EV) ② 剩余按当前 CPI 继续（典型 · 偏差延续） ETC = (BAC − EV) / CPI EAC = BAC / CPI ③ 同时考虑进度 + 成本影响 EAC = AC + (BAC − EV) / (CPI × SPI) 通用：VAC = BAC − EAC TCPI = (BAC − EV) / (BAC − AC) 挣值计值规则 50/50 规则：活动开始记完成 50%，完成记 100% （2021.05 案例原题） 0/100 规则：只有完成才记 100%
答题四件套：① 列数据 → ② 算指标 → ③ 写结论（成本超支/节约、进度落后/提前，要分开写）→ ④ 提建议（赶工、加强成本控制、调整资源）。只写数字不写公式 = 白丢过程分。

⑤其余领域 · 范围 / 沟通 / 干系人 / 立项

范围管理（2 次 / 35 分）

6 过程：规划范围管理 → 收集需求 → 定义范围 → 创建 WBS → 确认范围 → 控制范围
  • WBS 两种表示形式：树形结构图 / 缩进列表（表格） —— 2022.05 全国卷原题
  • 创建 WBS 步骤：识别分析可交付成果 → 确定 WBS 结构与编排方法 → 自上而下逐层分解 → 分配标识编码 → 核实分解程度是否恰当
  • 工作包 = WBS 最底层；控制账户 = WBS 中层管理点
  • 分解原则：100% 原则（子层之和 = 父层全部）；工作包以 80 小时或不超过一个汇报周期为宜；不跨职能；不含"活动"（活动是进度管理的事）
找错清单
  1. 无范围管理计划 / 需求管理计划
  2. 需求收集不充分，且未与客户确认签字
  3. 范围蔓延（客户不断加活）/ 镀金（项目组主动多做）
  4. WBS 分解不当：过粗漏项，或过细分解到"活动"
  5. 未做范围确认，可交付成果未正式验收
  6. 无需求跟踪矩阵，需求与交付物无法对应
  7. 范围变更未受控、未更新范围基准
  8. 无验收标准，导致验收时扯皮

沟通 + 干系人（3 次 / 59 分）

  • 沟通渠道数 = n(n − 1) / 2（n 为人数）
  • 三类沟通方式：交互式（会议、电话、视频会）、推式（邮件、报告、备忘录）、拉式（知识库、公告栏、门户）
  • 权力 / 利益方格（必考）：高权高利 → 重点管理；高权低利 → 令其满意；低权高利 → 随时告知；低权低利 → 监督（花最少精力）
  • 干系人分类模型：权力/利益方格、权力/影响方格、影响/作用方格、凸显模型（权力·紧急性·合法性）、干系人参与度评估矩阵
  • 参与度 5 档：不知晓 → 抵制 → 中立 → 支持 → 领导
找错清单
  1. 无沟通管理计划 / 沟通方式选择不当
  2. 干系人识别不全（漏了供应商、监管部门、最终用户、运维方）
  3. 未做干系人分析，未用权力/利益方格分类管理
  4. 沟通渠道单一、会议无纪要、信息未送达关键干系人
  5. 未及时报告项目状态，问题暴露后高层才知情
  6. 未管理干系人期望、未促进干系人参与
  7. 干系人登记册未随项目更新

立项管理（1 次 / 18 分）

  • 可行性研究 4 阶段：机会研究 → 初步可行性研究 → 详细可行性研究 → 项目评估
  • 初步可研可能出现的 4 种结果：① 肯定，可直接上详细可研 ② 肯定，转详细可研 ③ 需专题研究 ④ 否定，项目终止
  • 可研四大方面：技术可行性、经济可行性、运行环境可行性、其他方面（社会/法律/政策）
  • 项目论证含：项目运行环境评价、技术评价、财务评价、国民经济评价、不确定性与风险评价、综合评价
  • 卖方内部立项（系统集成商视角）：项目资源估算 → 资源分配 → 准备项目任务书 → 任命项目经理
  • 内部立项目的：把合同责任转移、明确资源投入、为绩效考核提供依据（不是为了签合同/收款）
