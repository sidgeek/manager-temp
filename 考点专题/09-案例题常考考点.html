②案例题的 3 种固定题型

每份卷 4 道题（17–22 分/题），题型逃不出这三类。认出题型 → 用对应套路 → 就是分数。

题型典型问法占比得分策略
A 计算题「计算关键路径/工期/总时差」「计算 PV、EV、AC、CV、SV、CPI、SPI、EAC」约 25%必须写公式 + 代入过程 + 结果 + 结论；结果算错但过程对仍有分
B 找错题 ⭐「结合案例，请指出本项目在 XX 管理方面存在的问题」约 50%分条写，每条「问题 + 案例依据」；写 6～8 条，多写不扣分
C 填空/判断/简述「请将 ①～⑤ 填入答题纸」「判断正误 √/×」「简述 XX 过程的输入/输出/作用」约 25%概念死记；判断题绝不留空，不会就蒙，蒙也有概率

⏱ 150 分钟答题节奏

  • 开场先花 3 分钟扫 4 道题，标记哪道是计算题 —— 先做计算题（约 30 分钟），答案唯一、写过程就拿分。
  • 找错题每题 20～25 分钟，先在草稿纸上按「计划 / 流程 / 文档 / 沟通 / 监控」5 个维度列点，再逐条补案例依据。
  • 最后留 10 分钟检查判断题有没有空着、计算题有没有漏写公式和结论。

③「找错题」万能模板 · 本页最值钱

找错题占案例约一半分值，且所有领域的找错角度高度同质。背下这套模板，任何领域都能套出 6～8 条。

标准答题句式（阅卷按关键词给分）

①（判断） 该项目未制定 / 未规范执行 XX 管理计划（或：XX 过程缺失）。
②（依据） 案例中「……（抄一句原文）」表明其在 XX 方面缺乏规范管理。
③（危害/正解） 导致……，正确做法应是……

8 个万能兜底角度（任何领域都能套）

  1. 无计划 —— 未制定 XX 管理计划，或计划未经评审/审批确认
  2. 职责不清 —— 无专人负责、无责任分配矩阵（RAM/RACI）
  3. 未走流程 —— 过程不完整：缺识别、缺分析、缺评审、缺批准
  4. 文档缺失 —— 未形成文档 / 文档未评审、未更新、未归档
  5. 未沟通 —— 未与干系人沟通、未获批准、未通知相关方
  6. 变更失控 —— 无变更控制，或变更后未更新计划与基准
  7. 无监控 —— 未做跟踪监督，问题发现滞后，未采取纠正措施
  8. 未复盘 —— 经验教训未总结、组织过程资产未更新

⏱ 时间/程度类加分表述

  • 「应该在 XX 阶段就完成，但案例中直到 YY 才……」→ 说明时机滞后
  • 「项目经理无权单独决定，应提交 CCB / 变更控制委员会 / 高层审批」→ 说明越权
  • 「仅有口头约定，未形成书面记录」→ 说明缺乏可追溯性
  • 「只做了 A，未做 B」→ 说明过程不完整（如只检查不预防、只识别不应对）

④进度管理 · 9 次 / 175 分（每次必考）

计算 + 找错双高频。计算部分详见 ② 关键路径 CPM、③ 三点估算、④ 进度压缩。

计算必背公式

六时标（先正推、后逆推） 正推：ES(首活动) = 0 EF = ES + 工期 多紧前活动 → ES = MAX(所有紧前 EF) 逆推：LF(末活动) = 总工期 LS = LF − 工期 多紧后活动 → LF = MIN(所有紧后 LS) 总浮动 TF = LS − ES = LF − EF TF = 0（或最小）→ 关键活动 自由浮动 FF = MIN(紧后活动 ES) − 本活动 EF 三点估算 PERT 期望工期 Te = (To + 4×Tm + Tp) / 6 标准差 σ = (Tp − To) / 6 项目总工期 T = Σ Te 项目总标准差 = √(Σ σ²) 概率：±1σ = 68.26% ±2σ = 95.46% ±3σ = 99.73% 进度压缩 赶工 = 加资源 → 加成本 快速跟进 = 并行 → 加风险 资源优化 资源平衡 = 改关键路径（工期变长） 资源平滑 = 不改关键路径

「进度方面存在的问题」找错清单

  1. 未制定进度管理计划／无进度基准，无法衡量偏差
  2. 活动定义不完整遗漏活动（常见：漏测试、漏上线、漏培训、漏数据迁移）
  3. 活动排序错误依赖关系（FS/SS/FF/SF）没理清，漏掉强制性依赖
  4. 工期估算不准凭经验拍脑袋，未用三点估算、未参考历史数据、未做专家判断
  5. 未识别关键路径精力平均分配，没盯住关键活动
  6. 关键路径上资源不足却去优化非关键路径的活动
  7. 进度压缩方法选择不当盲目赶工不看成本斜率；盲目并行不看返工风险
  8. 未做资源平衡/资源平滑人员严重过载、同一人同时被多个活动占满
  9. 进度监控缺失没有定期检查点，问题暴露太晚
  10. 出现延期后未及时纠偏未采取纠正措施或纠正措施无效

⑤质量管理 · 9 次 / 164 分（最好套模板）

三过程 + QA/QC 辨析（填空常考）

管理质量 QA（质量保证）控制质量 QC（质量控制）
关注过程、体系、过程改进可交付成果、是否达标
时机全过程（事前 / 事中）事后检查、验收前
手段质量审计、过程分析检查、测试、统计抽样、核查表
输出变更请求、质量报告核实的可交付成果、质量控制测量结果
口诀「QA 管过程防未病，QC 管结果查已病」

七种基本质量工具（年年考填空）

  • 因果图（鱼骨图 / 石川图）—— 找根本原因
  • 流程图 —— 展示过程步骤与可能出问题的环节
  • 核查表（计数表）—— 收集数据、统计缺陷频次
  • 帕累托图 —— 按频次排序 + 累计百分比，80/20 法则找"少数关键原因"
  • 直方图 —— 特殊形式条形图，描述集中趋势、分散程度、分布形状
  • 控制图 —— 判断过程是否受控（上下控制界限、连续 7 点在均值同侧判异常）
  • 散点图 —— 看两个变量之间的相关性

质量成本（判断分类常考）

一致性成本（主动投入）
  • 预防成本：培训、评审、过程改进、质量规划
  • 评估成本：测试、检查、破坏性测试、计量设备
非一致性成本（被动损失）
  • 内部失败：返工、废品、停工（交付前发现）
  • 外部失败：保修、退货、投诉、诉讼（交付后发现）

「质量管理方面存在的问题」找错清单

  1. 未制定质量管理计划或计划未经评审、未明确质量测量指标与验收标准
  2. QA 与 QC 职责混淆把"检查"当成"保证"，只做测试不做过程改进
  3. QA 缺乏独立性由开发人员兼任、或向项目经理汇报（QA 应保持独立，向高层/PMO 汇报）
  4. 未做质量审计无法验证质量过程的合规性
  5. 未做技术评审 / 设计评审或评审会由被评审者本人组织（应独立组织）
  6. 质量测量指标不明确需求不可度量，验收无标准
  7. 重检验轻预防一致性成本投入不足，只在末期"救火"
  8. 质量责任不清无责任分配矩阵，出了问题互相推诿
  9. 发现缺陷未做根本原因分析只改表面现象，同类问题反复出现
  10. 缺陷修复后未回归验证变更/返工后未确认是否真正解决

⑥整合管理 · 7 次 / 130 分（变更 · 配置 · 收尾）

整合管理的案例题就这三个壳，其中配置管理近三年明显升温（2023.05、2022.05 广东、2016.11 均考）。

A · 变更管理

八步流程 · 填空题原句
  • ① 提出与接受变更申请
  • ② 对变更的初审
  • ③ 变更方案论证
  • ④ CCB（变更控制委员会）审查批准
  • ⑤ 发出变更通知并实施
  • ⑥ 变更实施的监控
  • ⑦ 变更效果评估
  • ⑧ 判断变更后项目是否已纳入正常轨道
找错清单
  1. 无变更控制流程或流程不规范、未定义 CCB 职责
  2. 变更未书面化口头、电话、即时消息一句话就改了，无变更请求单
  3. 变更未经 CCB 审批就实施项目经理或开发人员擅自修改 （最常见）
  4. 未做变更影响分析没评估对范围/进度/成本/质量/风险/合同的影响
  5. 变更未通知干系人客户、团队、供应商不知情
  6. 变更后未更新计划与基准文档、进度基准、成本基准未同步
  7. 无变更日志变更无记录，无法追溯、无法统计
  8. 变更后未验证确认改完就走，没确认是否达到预期
  9. 变更频繁的根因未解决追溯到：需求未确认、范围不明确、合同条款含糊

B · 配置管理（近几年超高频）

6 项活动
制定配置管理计划 → 配置项标识 → 配置项控制 → 配置状态报告 → 配置审计 → 发布管理与交付
三库对照（判断题常考）
库别名存放内容权限
开发库动态库 / 工作库开发中、未评审的半成品开发者自己可改
受控库主库已评审通过、成为基线的配置项严格受控，须审批
产品库静态库 / 发行库已定型、可交付的产品只读
版本号规则
  • 草稿：0.x（如 0.68 —— 处于草稿状态）
  • 正式：x.y（如 V2.1 —— y 为小版本号，一般 y ∈ 0–9）
  • 修改：x.yz（如 V2.13 —— 正在修改中）
  • 配置审计两种：功能配置审计（符合功能需求吗）+ 物理配置审计（东西齐不齐、一致吗）
找错清单
  1. 未制定配置管理计划
  2. 未识别配置项／未给配置项编号、未定义命名规则
  3. 三库未建或混用开发库与受控库不分、直接改主库
  4. 未建立基线无需求基线 / 设计基线 / 产品基线
  5. 版本管理混乱文档版本与实物不一致、历史版本未保留
  6. 权限管理失控人人都可读写受控库
  7. 变更不走配置控制流程改了不申请、不记录、不评审
  8. 未做配置审计功能审计 + 物理审计都缺
  9. 无专职配置管理员或由开发人员兼职
  10. 未做配置状态报告配置项当前状态无人知晓

C · 项目收尾（2017.11 考过）

  • 收尾两类：合同收尾（结清合同、完成验收）+ 行政收尾（管理收尾）
  • 行政收尾核心：确认可交付成果已交付验收 → 项目档案归档 → 经验教训总结 → 释放资源 → 最终产品移交
  • 项目总结会：应在项目正式结束前召开；参加者含全体成员与主要干系人；讨论技术绩效、管理绩效、人员绩效、经验教训、遗留问题

⑦风险管理 · 7 次 / 123 分

7 过程 + 应对策略（填空必背）

规划风险管理 → 识别风险 → 定性风险分析 → 定量风险分析 → 规划风险应对 → 实施风险应对 → 监督风险
消极风险（威胁）积极风险（机会）
规避：消除原因 / 改计划开拓：确保机会一定发生
转移：外包 / 保险 / 合同条款分享：分给第三方共同争取
减轻：降低概率或影响提高：提高概率或正面影响
接受：被动 / 主动（留应急储备）接受：机会来了就顺势利用
上报：超出项目经理权限时上报高层 —— 对威胁和机会都适用

两个常考概念

  • 风险值 = 概率 × 影响，配合概率影响矩阵定风险等级
  • 应急储备：应对「已知-未知」风险，项目经理可直接动用，在成本基准内
  • 管理储备：应对「未知-未知」风险，须高层审批，不在成本基准内（总成本 = 成本基准 + 管理储备）
  • 风险审计：检查风险应对措施的有效性 + 风险管理过程的有效性
  • 风险登记册：始于识别风险过程，全项目持续更新

「风险管理方面存在的问题」找错清单

  1. 未制定风险管理计划无风险偏好、无概率影响矩阵、无风险预算
  2. 风险识别不充分只靠项目经理一人，未全员参与，未用专家判断/头脑风暴/德尔菲/SWOT
  3. 只识别威胁不识别机会
  4. 未做定性/定量分析没有优先级排序，眉毛胡子一把抓
  5. 无风险登记册或登记册未随项目推进更新
  6. 无风险责任人识别了风险但没人认领、没人跟踪
  7. 无应对措施或措施与风险严重程度不匹配
  8. 储备缺失或混用无应急储备；或把管理储备当应急储备用了
  9. 未做风险监控 / 风险审计
  10. 风险发生后才被动应对说明前期监控完全失效

⑧采购与招投标 · 5 次 / 88 分

招投标法定数字（背死，判断+找错双杀）

≥ 20 日招标文件发出 → 投标截止
15 日前招标文件澄清 / 修改须发出
5 人以上单数评标委员会人数
≥ 2 / 3技术经济专家占比
≥ 3 日中标候选人公示期

可不招标的情形：涉及国家秘密/安全、抢险救灾、需采用不可替代的专利或专有技术、采购人依法能够自行建设、需向原中标人采购否则影响施工/功能配套。

「招投标方面存在的问题」找错清单

  1. 应招标而未招标直接指定供应商；或化整为零规避招标
  2. 招标文件编制不规范含歧视性、倾向性条款，指定品牌或特定供应商
  3. 时间节点违规不足 20 日、澄清不足 15 日
  4. 评标委员会组成不合规人数非单数、专家比例不足、有利害关系者未回避
  5. 招标人与投标人串通开标前泄露标底、泄露其他投标人信息、暗示报价
  6. 开标前开启投标文件并透露给他人
  7. 中标候选人未公示或公示期不足 3 日
  8. 未在 30 日内签合同或所签合同与招标文件实质性内容不一致
  9. 中标人转包或违法分包
  10. 资格预审 / 资格后审程序错误

「合同管理方面存在的问题」找错清单

  1. 合同条款不明确范围、验收标准、知识产权归属、付款节点
  2. 无 SOW 或 SOW 不完整工作说明书缺：工作范围、交付物、验收标准、期限、地点
  3. 合同变更未签补充协议口头答应就算变更
  4. 未做合同交底项目团队不了解合同要求
  5. 索赔流程不当或超期未在 28 天内提出索赔通知
  6. 无合同管理台账合同文档未归档、付款与交付不匹配
  7. 验收无书面确认未取得客户签署的验收报告

⑨资源管理 · 6 次 / 107 分

必背理论（填空高频）

  • 团队发展 5 阶段：形成 Forming → 震荡 Storming → 规范 Norming → 成熟/发挥 Performing → 解散 Adjourning
  • 震荡期特征：成员间争执、互相指责、怀疑领导能力 —— 案例最爱考"判断当前处于哪个阶段"
  • 冲突解决 5 种（由弱到强）：回避/撤退 → 缓和/包容 → 妥协/调和 → 强迫/命令 → 合作/解决问题（合作最优、双赢）
  • 马斯洛 5 层次：生理 → 安全 → 社交（归属）→ 尊重 → 自我实现
  • 赫兹伯格双因素：保健因素（工资、工作条件、公司政策 → 消除不满）+ 激励因素（成就、认可、责任、成长 → 产生满意）
  • 项目经理 5 种权力：法定（合法）、奖励、强制（惩罚）、专家、感召（参照）
  • X 理论（人性惰、需强制）／Y 理论（人主动、愿负责）
  • RAM / RACI：确保每个工作包只有一个明确责任人（R 负责、A 批准、C 咨询、I 知情）

「人力资源管理方面存在的问题」找错清单

  1. 无人力资源管理计划 / 人员配备管理计划无资源日历，谁何时在岗不清楚
  2. 人员技能与岗位不匹配未做技能培训、未评估能力
  3. 一人身兼多职 / 资源冲突关键人员被同时抽调到多个项目
  4. 团队处于震荡期未有效引导冲突未及时干预，内耗严重
  5. 冲突处理方式不当一味回避（问题累积）或一味强迫（士气受损）
  6. 无激励机制只靠加班压任务，忽视马斯洛/双因素需求
  7. 沟通不足信息不透明，成员不了解项目目标与进展
  8. 无责任分配矩阵职责边界模糊，出问题互相推诿
  9. 无绩效考核或考核标准不公平、不公开
  10. 人员离职无知识转移无文档沉淀、无备份人员

⑩挣值 EVM · 速查（案例必拿分）

完整讲解见 ① EVM 挣值分析专题，这里只放冲刺速查。

绩效（现状） CV = EV − AC <0 成本超支 SV = EV − PV <0 进度落后 CPI = EV / AC <1 超支，>1 节约 SPI = EV / PV <1 落后，>1 超前 预测（未来 · 关键看典型 / 非典型） ① 剩余按原预算完成（非典型 · 已纠偏） ETC = BAC − EV EAC = AC + (BAC − EV) ② 剩余按当前 CPI 继续（典型 · 偏差延续） ETC = (BAC − EV) / CPI EAC = BAC / CPI ③ 同时考虑进度 + 成本影响 EAC = AC + (BAC − EV) / (CPI × SPI) 通用：VAC = BAC − EAC TCPI = (BAC − EV) / (BAC − AC) 挣值计值规则 50/50 规则：活动开始记完成 50%，完成记 100% （2021.05 案例原题） 0/100 规则：只有完成才记 100%
答题四件套：① 列数据 → ② 算指标 → ③ 写结论（成本超支/节约、进度落后/提前，要分开写）→ ④ 提建议（赶工、加强成本控制、调整资源）。只写数字不写公式 = 白丢过程分。

⑪其余领域 · 范围 / 沟通 / 干系人 / 立项

范围管理（2 次 / 35 分）

6 过程：规划范围管理 → 收集需求 → 定义范围 → 创建 WBS → 确认范围 → 控制范围
  • WBS 两种表示形式：树形结构图 / 缩进列表（表格） —— 2022.05 全国卷原题
  • 创建 WBS 步骤：识别分析可交付成果 → 确定 WBS 结构与编排方法 → 自上而下逐层分解 → 分配标识编码 → 核实分解程度是否恰当
  • 工作包 = WBS 最底层；控制账户 = WBS 中层管理点
  • 分解原则：100% 原则（子层之和 = 父层全部）；工作包以 80 小时或不超过一个汇报周期为宜；不跨职能；不含"活动"（活动是进度管理的事）
找错清单
  1. 无范围管理计划 / 需求管理计划
  2. 需求收集不充分，且未与客户确认签字
  3. 范围蔓延（客户不断加活）/ 镀金（项目组主动多做）
  4. WBS 分解不当：过粗漏项，或过细分解到"活动"
  5. 未做范围确认，可交付成果未正式验收
  6. 无需求跟踪矩阵，需求与交付物无法对应
  7. 范围变更未受控、未更新范围基准
  8. 无验收标准，导致验收时扯皮

沟通 + 干系人（3 次 / 59 分）

  • 沟通渠道数 = n(n − 1) / 2（n 为人数）
  • 三类沟通方式：交互式（会议、电话、视频会）、推式（邮件、报告、备忘录）、拉式（知识库、公告栏、门户）
  • 权力 / 利益方格（必考）：高权高利 → 重点管理；高权低利 → 令其满意；低权高利 → 随时告知；低权低利 → 监督（花最少精力）
  • 干系人分类模型：权力/利益方格、权力/影响方格、影响/作用方格、凸显模型（权力·紧急性·合法性）、干系人参与度评估矩阵
  • 参与度 5 档：不知晓 → 抵制 → 中立 → 支持 → 领导
找错清单
  1. 无沟通管理计划 / 沟通方式选择不当
  2. 干系人识别不全（漏了供应商、监管部门、最终用户、运维方）
  3. 未做干系人分析，未用权力/利益方格分类管理
  4. 沟通渠道单一、会议无纪要、信息未送达关键干系人
  5. 未及时报告项目状态，问题暴露后高层才知情
  6. 未管理干系人期望、未促进干系人参与
  7. 干系人登记册未随项目更新

立项管理（1 次 / 18 分）

  • 可行性研究 4 阶段：机会研究 → 初步可行性研究 → 详细可行性研究 → 项目评估
  • 初步可研可能出现的 4 种结果：① 肯定，可直接上详细可研 ② 肯定，转详细可研 ③ 需专题研究 ④ 否定，项目终止
  • 可研四大方面：技术可行性、经济可行性、运行环境可行性、其他方面（社会/法律/政策）
  • 项目论证含：项目运行环境评价、技术评价、财务评价、国民经济评价、不确定性与风险评价、综合评价
  • 卖方内部立项（系统集成商视角）：项目资源估算 → 资源分配 → 准备项目任务书 → 任命项目经理
  • 内部立项目的：把合同责任转移、明确资源投入、为绩效考核提供依据（不是为了签合同/收款）
