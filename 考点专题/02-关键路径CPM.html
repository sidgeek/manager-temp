①知识地图

关键路径法（CPM）通过 6 个时间参数描述每个活动，再把所有 TF=0 的活动串起来 = 关键路径 = 项目总工期。

4 种活动依赖关系

类型英文说明
FSFinish-to-Start完成-开始（最常用，前者完成后后者才能开始）
SSStart-to-Start开始-开始（两者同时开始）
FFFinish-to-Finish完成-完成（两者同时完成）
SFStart-to-Finish开始-完成（极少用）

依赖关系的 4 种性质（成因）· 别和 FS/SS/FF/SF 混

性质别称含义例子
强制依赖硬逻辑客观规律 / 合同要求，不能改先打地基才能盖楼
选择性依赖软逻辑 / 优先团队按经验偏好定，可调整先做 A 模块再做 B 模块
外部依赖—依赖项目外部的东西等政府审批后才能开工
内部依赖—项目内部活动之间的依赖本项目两张图纸先后出
  • 两组概念别混：FS / SS / FF / SF 说的是"怎么挂钩"（哪两个时点对齐）；强制 / 选择性 / 外部 / 内部 说的是"为什么有这条依赖"（成因）。
  • 选择性依赖是"可优化"的：快速跟进（并行）本质就是打破选择性依赖。
  • 软考常考：给情景判断属于哪种性质（如"等外部审批"→ 外部依赖；"法规要求必须先做"→ 强制依赖）。
🧠 举例理解 · FF 到底指什么？两个任务必须同时完成吗
展开讲解
【先分清】本页 FF 出现两次，含义完全不同：
· 4 种依赖关系里的 FF = Finish-to-Finish（完成-完成），描述依赖类型；
· 6 个时间参数里的 FF = Free Float（自由浮动时间） = min(紧后 ES) − 本活动 EF。
这里讲的是第一种。

【Finish-to-Finish 的含义】紧后活动的"完成"挂钩紧前活动的"完成" → 紧后不能早于紧前完成。
公式（无 lag）：B 的 EF ≥ A 的 EF。

【和 FS 对比：一个卡起点、一个卡终点】
· FS 完成-开始：B 的 ES ≥ A 的 EF（钩"开始"）
· FF 完成-完成：B 的 EF ≥ A 的 EF（钩"完成"）

【回答"必须同时完成吗"】不是。完成时间只是"挂钩 / 对齐"，分三种情况：
① 紧后较短 → 被拖到与紧前同一天收尾，看起来"同时完成"（A=5、B=3 → B 的 EF=5）。
② 紧后更长 → 反而更晚完成，并非同时（A=3、B=5 → B 的 EF=5）。
③ 带 lag → B 的 EF ≥ A 的 EF + lag（如"紧前完成后 2 天内紧后也必须完成"）。

【直观例子】A = 铺电线 5 天，B = 装灯具 2 天，关系 FF → "灯必须在电线铺完后才能装完"，B 被压到 A 完工那天收尾。

【口诀】FS 卡住"起点"，FF 卡住"终点"；FF ≠ 同时完成，只表示"不能比紧前先完事"。
🧠 举例理解 · SF（开始-完成）是什么？为什么极少用
展开讲解
【命名规律】关系名的两个字母 = 紧前的节点 → 紧后的节点：
· FS：紧前完成 → 紧后开始（B 的 ES ≥ A 的 EF）
· SS：紧前开始 → 紧后开始（B 的 ES ≥ A 的 ES）
· FF：紧前完成 → 紧后完成（B 的 EF ≥ A 的 EF）
· SF：紧前开始 → 紧后完成（B 的 EF ≥ A 的 ES）

【SF 一句话】紧后活动的"完成"要等到紧前活动"开始"之后 —— 紧前不启动，紧后就完不成。

【为什么反直觉 / 极少用】正常逻辑都是"做完才能开始"（FS）。SF 是"你一开始，我才能结束"，现实中很少有"依赖别人的开始才能收尾"的事，所以四种里最冷门。

【经典场景 · 新旧系统切换】
A = 新系统上线运行（紧前）；B = 旧系统停用下线（紧后，SF 关系）。
含义：旧系统不能早于新系统上线就停用 → 必须等新系统一开始跑，旧系统才能下线。
公式：B（旧系统停用）的 EF ≥ A（新系统上线）的 ES。
目的是保证业务不断档：新系统没起来前，旧系统绝不能停。

【和另外三种的区别 · 记 3 句】
· SF 是唯一"挂钩紧前的开始 + 紧后的完成"的组合，其余三种都不会同时出现"前开始 + 后完成"。
· 它是"防中断"型约束：替代方案就位前，旧的东西不能停。
· 软考里基本只考"认概念"——问"哪种依赖最少用"答案就是 SF。

【口诀】SF = "你开始，我才结束"；反直觉 + 极少用，两个标签记住就够。

提前量（Lead）· 滞后量（Lag）

  • 滞后量 Lag：后活动必须等一段才能开始/完成，记作 +X 天。例：FS + 3 天 → 紧前完成后要等 3 天，紧后才能开始（养护、审批、固化期）。
  • 提前量 Lead：后活动可以提前开始/完成，记作 −X 天。例：FS − 2 天 → 紧前完成前 2 天，紧后就能开始（搭接 Overlap）。
  • 记忆：Lead = 快一步（提前、搭接）；Lag = 慢一步（等一等）。Lead 提速但增风险，Lag 多为客观等待。
  • 带 Lead / Lag 的四个公式（做题直接套）：
  • FS：紧后 ES = 紧前 EF + lag（lead 取负）
  • SS：紧后 ES = 紧前 ES + lag（lead 取负）
  • FF：紧后 EF = 紧前 EF + lag（lead 取负）
  • SF：紧后 EF = 紧前 ES + lag（lead 取负）
  • 关键：正推算 ES 时，先把 lag / lead 加减进公式，再和其他紧前取最大值。

6 个时间参数

缩写含义推算方向
ESEarliest Start · 最早开始正推（左→右）
EFEarliest Finish · 最早完成正推
LSLatest Start · 最晚开始逆推（右→左）
LFLatest Finish · 最晚完成逆推
TFTotal Float · 总浮动时间= LS − ES = LF − EF
FFFree Float · 自由浮动时间= min(紧后 ES) − 本活动 EF

总时差 TF vs 自由时差 FF · 别再混

对比项总时差 TF（Total Float）自由时差 FF（Free Float）
公式TF = LS − ES = LF − EFFF = min(紧后 ES) − 本活动 EF
含义不影响总工期能拖多久不影响紧后最早开始能拖多久
大小关系FF ≤ TF（自由时差不会大于总时差）
判定关键TF=0 → 关键活动FF=0 不一定关键，还要看 TF
  • 终点活动的 FF 定义为 0（它没有紧后）；TF=0 时 FF 必为 0，反之不成立。
  • 问"延误是否影响总工期"用 TF：延误 X 天，TF ≥ X 不影响，TF < X 就拖累总工期。
  • 问"延误是否影响紧后最早开始"用 FF：延误 X 天，FF ≥ X 不影响紧后。
  • 一句话：TF 看全局（总工期），FF 看局部（紧后）。

七格图（单代号节点框）· 6 个时间参数怎么摆

  • 别名：节点图 / 活动节点框 / 单代号节点，是单代号网络图（PDM）里表示一个活动的方框。
  • 作用：把「网络图」与「6 个时间参数」二合一——一个框同时装下各参数与工期，是软考手算最实用的模板。
  • 七个格 = 活动名称、工期、ES、EF、LS、LF、TF。注意：七格图只含 TF、不含 FF；若题目要自由时差，用公式 FF = min(紧后 ES) − 本活动 EF 单独算。
  • 位置规律（记这一句就够）：左列是"开始"（左上 ES、左下 LS），右列是"完成"（右上 EF、右下 LF），中列装"工期 / 名称 / TF"（中上工期、中行活动名称横跨整行、中下 TF）；顶行活动主体（ES、工期、EF），底行逆推结果（LS、TF、LF）。
① 空白七格图 · 每个格放什么
顶行（左→中→右）：ES / 工期 D / EF；中行整行：活动名称；底行（左→中→右）：LS / 总时差 TF / LF。中列三格（中上-工期、中行-名称、中下-TF）也是关键之一。
② 填好数据的例子（活动 C · TF=1，非关键）
以活动 C（工期 5）为例：顶行：ES=4、D=5、EF=9（正推）；中行：C（活动名称）；底行：LS=5、TF=1、LF=10（逆推）。TF = LS − ES = 1 ≠ 0 → 非关键活动；TF=0 才是关键活动（本题 B、D、E 的 TF=0）。
  • 填图顺序（正推 → 逆推 → 求 TF）：
  • ① 照网络图给每个活动标好工期（中上格）。
  • ② 正推填顶行：起点 ES=0；多紧前取最大 EF；EF = ES + 工期（左→右做加法）。
  • ③ 逆推填底行：终点 LF = 总工期；多紧后取最小 LS；LS = LF − 工期（右→左做减法）。
  • ④ 算 TF = LS − ES = LF − EF 填底行中格；TF=0 → 关键活动。
  • ⑤ 把所有 TF=0 的活动首尾相连 = 关键路径；需要时再算 FF = min(紧后 ES) − 本活动 EF。

进度网络图分类（单代号 vs 双代号）

方法别称图形表示特点
PDM前导图法 / 单代号网络图（AON）节点 = 活动；箭线 = 依赖关系最常用；支持 FS / SS / FF / SF 四种关系；无虚活动
ADM箭线图法 / 双代号网络图（AOA）箭线 = 活动；节点 = 事件（时点）需用虚箭线表逻辑；一般只支持 FS；节点编号要求 i < j
  • 软考计算题绝大多数用单代号（PDM）：看图先认"活动写在圈里还是箭线上"。
  • 其他图：时标网络图（横轴为时间，可直接读出浮动时间）、甘特图 / 横道图（直观但看不出依赖与关键路径）、里程碑图（只标关键时点）。

时标网络图 · 怎么一眼读出浮动时间

  • 时标网络图：横轴是时间刻度，箭线的水平长度 = 工期，节点落在时间刻度上。
  • 读关键路径：全程没有波形线的路径就是关键路径。
  • 读自由时差：箭线末端带的波形线长度 = 自由时差 FF。
  • 总时差 TF 不能直接读，要沿路径累加剩余；波形线之和最小的那条路径 = 关键路径。
  • 优势：不用算 6 个参数，肉眼看波形线就能找关键路径、读浮动，是双代号网络图最直观的变形。
示意 · 紫色波形线 = 自由时差
上方 A→B 全程无波形线 → 在关键路径上；下方 C 末端出现紫色波形线，长度 = 自由时差 FF = 1 天 → C 拖 1 天不影响 B 的最早开始。

单代号 vs 双代号 · 同一道题，两种画法

  • 题目：A = 3 天、B = 4 天，A、B 都完成才能开始 C = 2 天。求总工期与关键路径。
① 单代号网络图（PDM / AON）—— 活动写在「节点」里
节点 = 活动（圈里写活动名 + 工期），箭线 = 依赖关系。A、B 各自连到 C，一眼看出"C 要等 A、B 都完成"。
② 双代号网络图（ADM / AOA）—— 活动写在「箭线」上
箭线 = 活动（线上写活动名 + 工期），节点 = 事件（只是时点，不干活）。C 要等 A、B 都完成，但 A 结束在节点 2、B 结束在节点 3 —— 靠一条虚线（虚活动，0 天）把节点 2 的逻辑"汇"到节点 3，C 才能正确地等两边。
③ 两种画法对比结论
  • 两条路径：A→C = 3 + 2 = 5 天；B→C = 4 + 2 = 6 天。
  • 取最长 → 总工期 6 天，关键路径 B → C（两种图画出来结果完全一致）。
  • 区别只在"画法"：单代号活动在圈里，双代号活动在箭上；双代号多出的虚活动只是"接线员"，本身不耗时。
  • 软考里看活动写在哪里就能判定是单代号还是双代号，计算逻辑完全通用。

虚活动（虚工作）· 双代号网络图专用

  • 只在双代号网络图（ADM/AOA）中出现，用虚箭线表示，工期 = 0、不消耗资源。
  • 作用一：表达实际不存在的逻辑依赖（图面画不出"两个紧前都完成才能开始某活动"时靠它连接）。
  • 作用二：避免编号歧义——两个相邻节点间不能有多条同向箭线，否则无法区分活动。
  • 易错：虚活动不是真实工作，算路径长度时计 0，但它是逻辑链上的必经环节。

项目总工期的概念

  • 定义：在满足所有依赖关系的前提下，完成整个项目所需的最短时间。
  • 公式：总工期 = 关键路径的长度 = 从起点到终点最长那条路径的时长。
  • 为什么取"最长"？多条路径并行推进时，项目必须等最慢的那条走完才算结束。
  • 注意：总工期 ≠ 所有活动工期之和（并行活动会重复相加），也 ≠ 最短路径。
  • 正推法中终点活动的 EF = 总工期；关键路径一旦转移，总工期可能随之改变。

CPM / PERT / 关键链 三种方法辨析

方法工期取值侧重点特点
CPM 关键路径法确定值（单一工期）时间-成本权衡求最长路径 = 总工期；可压缩赶工
PERT 计划评审三点估算（乐观/最可能/悲观）概率 / 不确定性算期望工期与标准差，求"按期完工概率"
关键链 CCM考虑资源约束资源受限下的进度把安全时间集中为缓冲（项目缓冲 PB、接驳缓冲 FB）
  • CPM vs PERT 一句话：CPM 是"确定的"（工期给定），PERT 是"概率的"（工期用三点估算 + 概率）。
  • 关键路径法假设"资源无限"；一旦资源受限，就用关键链法（CCM），靠缓冲管理风险，而非给每个活动留安全时间。
  • 三种方法找"关键路径"思路一致：最长（或最紧）的那条链决定总工期。

③计算思路 · 建模 → 正推 → 逆推

第 0 步 · 输入形式与建模（先读懂题，再画图）

  • 形式一 · 紧前关系表（最常见）：给一张表，列为「活动 | 工期 | 紧前活动」，需要你自己转成网络图。
  • 形式二 · 直接给网络图：给单代号或双代号图，让你算时间参数 / 关键路径，不用转换，直接正推逆推。
  • 形式三 · 文字描述：用文字说"A 完成后 B、C 才能开始"，等价于表格，先转成表再画图。
  • 其他：甘特图 / 横道图、里程碑图、已给部分时间参数（ES / EF…）让你补全。
  • 表格 → 网络图 三步转换：
  • ① 找出没有紧前的活动 → 全部挂到「开始」（起点组）。
  • ② 逐个活动：从它的每一个紧前活动各引一条箭线指向它（多个紧前要全部连，别漏）。
  • ③ 找出没有紧后的活动 → 全部汇到「结束」（终点组）。
  • 大坑：表格给的是"紧前"还是"紧后"要看清楚，方向别画反（紧前 = 箭头从它出发指向当前活动）。

正推（Forward Pass）· 算 ES / EF

  • 从起点开始，逐个活动计算；起点活动 ES = 0。
  • EF = ES + 工期。
  • 某活动有多个紧前时，ES 取所有紧前 EF 中的最大值（FS 关系）。

逆推（Backward Pass）· 算 LS / LF

  • 从终点开始，逐个活动逆推；终点活动 LF = 总工期（或正推 EF）。
  • LS = LF − 工期。
  • 某活动有多个紧后时，LF 取所有紧后 LS 中的最小值。

浮动时间与关键路径

  • TF = LS − ES（或 LF − EF），TF = 0 的活动为关键活动。
  • 把所有 TF=0 的活动连起来 = 关键路径；路径总长 = 总工期。
  • FF 反映"本活动延误多少天不会影响紧后最早开始"，FF ≤ TF。
  • 问"延误 X 天是否影响总工期" → 看该活动 TF 是否 < X。

关键路径怎么判断（两种方法）

  • 方法一 · 路径列举法（适合活动少的小题）：列出起点 → 终点的所有路径 → 每条路径工期相加 → 最长的那条就是关键路径，其长度 = 总工期。
  • 方法二 · 时间参数法（通用，推荐）：先正推算 ES/EF、再逆推算 LS/LF → 求 TF = LS − ES → 把所有 TF = 0 的活动首尾相连 = 关键路径。
  • 关键路径的性质：① 是耗时最长的路径，长度即总工期；② 可能不止一条（多条并列最长）；③ 路径上任一活动延误，必然导致总工期延误；④ 只有压缩关键路径上的活动才能缩短工期。
  • 易错点：关键路径是"最长"不是"最短"；活动数多时别硬套列举法（组合爆炸），直接上时间参数法。

④规律与注意点

💡 关键路径可能不止一条：题目常埋"两条关键路径"的坑，TF=0 的活动必须全部连起来。 💡 ES 起点：多数题目约定从 0 开始，但部分题目从 1 开始，以题图为准，别生搬硬套。 💡 压缩只动关键路径：压缩非关键活动不影响总工期；压缩后关键路径可能转移，需重新计算。 💡 FF 易错：FF 是"影响紧后最早开始"，不是"影响总工期"；二者混淆是常见失分点。 💡 虚拟活动（虚工作）：用虚线箭头表示，工期为 0，仅表示逻辑依赖关系。 💡 lead / lag：lead 表示提前（SS 提前 X 天开始），lag 表示滞后（FS 滞后 X 天开始）。

特殊情况与转换陷阱（高频失分点）

🟥 多起点 / 多终点：表里若有多个活动都没有紧前，画图常加一个虚拟起点统一挂接；多个活动都没有紧后，加一个虚拟终点。双代号尤其要求起点、终点各只有一个。 🟥 编号规则（双代号）：节点编号必须 i < j（箭头从小号指向大号）；两个节点间只能有一条箭线，出现多条必须用虚活动拆开。 🟥 不允许回路：依赖关系不能成环（A→B→A），一旦画成环，多半是"紧前 / 紧后"方向看反了。 🟥 紧前 vs 紧后方向：表写"紧前"→ 箭线从紧前出发指向本活动；若给的是"紧后"，方向正好相反 —— 这是最容易画反的坑。 🟥 起点从 0 还是 1 开始：多数题从 0，部分教材从 1，以题图 / 题意为准，且整题保持一致。 🟥 工期可为 0：除虚活动外，少数"里程碑式活动"工期也可能是 0，别当成错误。 🟥 关键路径会转移：压缩某条关键路径后，原本非关键的路径可能变成新的关键路径，必须重新正推逆推。 🟥 中段活动也可能关键：不要只看路径总长，用 TF = 0 判断最稳妥。

⑤例题演练

例题：某项目有 A→C、B→C、A→D、B→D、C→E、D→E 六个 FS 关系。A=3 天、B=4 天、C=5 天、D=6 天、E=2 天。求总工期、关键路径、各活动 TF。
显示答案
正推：
A：ES=0, EF=3
B：ES=0, EF=4
C：ES=max(3,4)=4, EF=9
D：ES=max(3,4)=4, EF=10
E：ES=max(9,10)=10, EF=12
总工期 = 12 天

逆推：
E：LF=12, LS=10
C：LF=min(LS of E)=10, LS=5
D：LF=min(LS of E)=10, LS=4
B：LF=min(LS of C, LS of D)=min(5,4)=4, LS=0
A：LF=min(LS of C, LS of D)=min(5,4)=4, LS=1

TF：
A：LS−ES=1−0=1
B：0−0=0
C：5−4=1
D：4−4=0
E：10−10=0

关键路径：B → D → E（总工期 4+6+2=12 天 ✓）
